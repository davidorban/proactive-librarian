# ADR-004: Source of truth — PDFs canonical, derived markdown is a disposable cache

- **Status**: proposed
- **Date**: 2026-05-17
- **Tags**: storage, source-of-truth

## Context

The retrieval backend needs searchable text. PDFs are binary; markdown is what backends index. Two options:

1. **PDF canonical, markdown derived** — keep PDFs as authoritative artefacts; extract them once to a markdown cache; the backend indexes the cache. PDFs may or may not be version-controlled; the cache is always reproducible from PDFs.
2. **Markdown canonical, PDFs derivative or discarded** — extract once, treat the markdown as the truth. PDFs become optional / archival. Saves storage but loses the original artefact, page-level visual fidelity, and the ability to cite to a viewable physical document.

The primary use case is **citation in deliverables aimed at other humans** (memos, decks, briefs). Citing to a markdown extraction is unprofessional — readers expect a real PDF when they click the link. Throwing PDFs away also discards any semantic structure encoded in the directory layout.

## Decision

**PDF is canonical.** The derived markdown lives under `<derived_dir>/<rel-pdf-stem>/` and is treated as a reproducible cache.

The cache is:
- Gitignored by default (the example `.gitignore` excludes `.derived/` and `**/.derived/`).
- Regenerated by `librarian ingest` on demand. Idempotent on file sha1 — reruns only re-extract changed/new PDFs.
- Never edited by hand. Any manual edit will be wiped on the next ingest.

Each per-PDF directory includes a sibling `_meta.json` carrying source-pdf-path, subject, geography, page count, file size, sha1, ingestion date, and a `derived_version` field for future format migrations.

## Consequences

### Positive
- Original artefacts preserved. Citations point at viewable PDFs.
- Cache is recoverable from scratch — losing `.derived/` is annoying, not catastrophic.
- Sha1-based idempotency makes incremental ingest cheap (often sub-minute even for 1k+ PDF libraries).
- Per-PDF metadata sidecar carries category/geography hints into the cache for future filtered queries.

### Negative
- Storage cost roughly doubled vs. markdown-only (PDFs typically dwarf extracted text, so the cache is small — but it's still extra bytes).
- Two artefacts to keep in sync; the "no manual edits to `.derived/`" convention must be enforced socially, not by the filesystem.
- Initial ingest of a large library is slow (30+ minutes for ~1.4k PDFs). The CLI shows progress and is resumable, but the first run is unavoidably wall-clock-bound.

### Neutral
- Decision is reversible at moderate cost: switching to "markdown canonical" would mean reorganising the cache, updating output to reference `.md` files, and accepting the loss of PDF citations.
